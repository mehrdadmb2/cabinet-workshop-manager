# Cloudflare Worker — Telegram Backup v3

## Variables / Secrets
Create these in **Workers & Pages → your Worker → Settings → Variables and Secrets**.

### Secret
`TELEGRAM_BOT_TOKEN`

Paste the NEW token generated by BotFather. Never commit it to GitHub.

### Text or Secret
`TELEGRAM_CHAT_ID`

Recommended value for your current private chat: `381200758` (replace it if your target chat changes).

### Text

Optional:
`BACKUP_SHARED_KEY`
`TELEGRAM_THREAD_ID`

## Critical Telegram requirement
A bot cannot normally start a private conversation with a user who has never opened the bot. Open the bot in Telegram and press **Start** / send `/start` before testing.

The `/test-telegram` endpoint performs the real chain:
1. `getMe` — token validation.
2. `getChat` — Chat ID/access validation.
3. `sendMessage` — real message delivery test.

This is intentionally stricter than a token-only test.

## Deploy
Use the Cloudflare dashboard's **Deployments → Create deployment** or Wrangler.

For Wrangler:
```bash
npx wrangler deploy cloudflare-worker/worker.js --config cloudflare-worker/wrangler.toml
```

Then open:
`https://YOUR-WORKER/health`

You should see `telegramConfigured: true`.

Then open the web app → Settings → **تست واقعی Telegram**. A real Telegram message should arrive.

## Security
Telegram token must stay in Cloudflare Secrets. Cloudflare documents Worker secrets as encrypted bindings available through the `env` object. Do not place tokens in frontend code or GitHub files.
